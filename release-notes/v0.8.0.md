## Additions

- `workingIndicator.intervalMs` and `thinkingIndicator.intervalMs` set how often the indicator animators ask for a full re-render. Both animate a status label, not a spinner, so 100 ms still reads as smooth while cutting render pressure roughly threefold on long sessions. `PRETTY_WORKING_INTERVAL_MS` / `PRETTY_THINKING_INTERVAL_MS` override the file. Values below 33 ms are clamped to that floor, and the default is unchanged (#18, thanks @october2823).
- `userRail` takes a `#rrggbb` and draws a one-cell tinted bar left of user messages instead of a full-width background. ANSI cell backgrounds are opaque per cell — SGR has no alpha — so painting `userMessageBg` kills the blur on acrylic and translucent terminals. The rail carries the tint while the rest of the width keeps showing through. Absent or invalid disables it (#18, thanks @october2823).

## Fixes

- `ls` header count no longer includes the SDK's `[N entries limit reached…]` notice line.
- `toolStyle: "claudecode"`: settled tool groups were cached on a key of width, member count and first/last tool id. Host rebuild paths (`/tree` navigation, fork, reload) reuse tool ids with equal or larger counts, so those keys hit and served rows whose mouse handlers pointed at dropped components — a click could expand a removed tool. A hit now requires the same member components and the same result state per tool, and the cache moved from module scope to per-container state (#17, thanks @october2823).
- `toolStyle: "claudecode"`: a restored session whose tool call never got a result showed a single frozen `Running` frame that only moved when a scroll forced a redraw. Those calls are now reported as `interrupted`, both in a group summary and on a lone row, and the state survives a later run that flips the agent back to active.
- `toolStyle: "claudecode"`: the cached-group store kept entries for every width ever rendered, so on a long session a few resizes filled the cap and nothing at the current width could be cached — the pre-cache slowdown came back. The store now clears when the width or theme changes instead of keying on them.

## Maintenance

- README and `pi-pretty.example.json` document the three new keys and both environment variables.
- Regression coverage for cache identity, per-container state, interrupted rows, resize invalidation, and the `userRail` wrapper (including that a rail row stays within the width it was given).
