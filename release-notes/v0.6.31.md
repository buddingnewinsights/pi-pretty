## Pi 1.1.0 rendering support

- Self-rendered `read`, `bash`, `ls`, `find`, and `grep` output now honors Pi's `outputPad` setting. Older hosts retain the one-space default, and expanded find results keep their directory/file hierarchy at padding zero.
- Execution-time displays prefer the host's recorded `durationMs`, including `0ms` and failed bash calls. Existing elapsed metadata remains a fallback for older hosts.
- `read` preserves the SDK's `outputSchema`, so codemode keeps structured read results.
- Padding changes are handled consistently by read highlighting and bash render caches; stale highlight work cannot overwrite a newer view.
- The development SDK and both lockfiles are aligned with Pi 1.1.0; runtime peer ranges are unchanged.

### Verification

- 313 tests passing across 20 files.
- Typecheck and production build passing.
- No lint errors; existing source warnings remain.

### Known limitation

The existing expanded-read code-row width at the default padding can exceed the terminal budget by one column. This release preserves that default behavior; larger custom padding no longer increases the overflow.

This GitHub release does not publish the package to npm.
